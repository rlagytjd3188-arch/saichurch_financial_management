# 사이교회 재무관리 1.3.0 구현·운영 보고서

## 1. 구현한 기능

기존 Java 25 / Spring Boot / Swing·FlatLaf / 암호화 H2 / Flyway 구조를 유지했습니다. 기존 예산·회계 연도·수입/지출·기존 보고서·가져오기·백업 메뉴를 남기고 브라우저 기반 회계·헌금·통계 화면을 추가했습니다. 앱 표시명은 사이교회 재무관리로 바꿨으며, 데이터 호환성을 위해 패키지명·백업 확장자·실행 파일 이름은 유지했습니다.

비밀번호는 정규화 후 유니코드 문자 수 기준 **4~64자**입니다. 숫자 네 자리·반복 문자도 사용할 수 있습니다. 최초 관리자 설정·사용자 생성·비밀번호 변경은 같은 정책을 사용하고, 기존 비밀번호 해시는 유지합니다.

## 3. DB 구조

| 테이블 | 내용 |
|---|---|
| `ACCT_ACCOUNT` | 코드·계정명·자산/부채/순자산/수익/비용 유형·활성 여부 |
| `ACCT_ENTRY` | 분개 일자·회계 연도·적요·원본 거래 ID·역분개 대상·생성 시각 |
| `ACCT_LINE` | 분개별 계정·차변·대변 정수 금액 |

| `OFFERING_TYPE` | 7개 기본 헌금 종류와 사용자 추가 종류·활성 여부 |

`FINANCIAL_RECORD.CANCELLED`와 `CONTACT.CREATED_AT`을 추가합니다. 기존 연락처의 CREATED_AT은 migration 적용 시각이며 실제 과거 등록일을 추정한 값이 아닙니다. 금액은 기존과 같은 원 단위 정수이며 합계는 BigInteger/DB NUMERIC로 계산합니다.

## 4. Migration

V1~V3을 수정하지 않고 V4를 추가했습니다. 기존 거래를 삭제·재작성하지 않습니다. 기본 계정 21개, 헌금 종류 7개, 공개 OFF 기본값을 추가합니다. 이전 거래마다 REVIEW 연결만 만들고 임의 분개·헌금 배분을 만들지 않습니다. 실제 운영 DB에 적용하기 전 앱 백업이 필요합니다. 구버전으로 되돌릴 때 새 DB를 구버전에서 열지 말고 업데이트 전 백업을 사용하세요.

## 5. 기존 데이터 처리

기존 H2 거래·예산·회계 연도·사람·금액·메모를 유지합니다. 원본 합계와 복식부기 합계는 REVIEW가 남아 있으면 다를 수 있으며 화면에 검토 건수를 표시합니다. 거래 상세에서 자산·수익/비용 계정과 헌금 여부를 확인하면 해당 원본을 연결합니다. 확인 전 자료가 복식부기 합계에 들어간 것처럼 표시하지 않습니다.

이 작업의 테스트는 모두 합성 자료와 임시 DB로 실행했습니다. 운영 H2 파일을 열거나 초기화하지 않았습니다. 이전 Next.js SQLite·엑셀의 H2 자동 변환은 포함되지 않으며 원본 파일과 백업 브랜치를 보존했습니다.

## 6. 복식부기 처리

일반 수입: 자산 차변 / 수익 대변. 일반 지출: 비용 차변 / 자산 대변. 기본 단일 운영 통장은 보통예금입니다. 기존 데스크톱에서 새로 입력한 항목은 기본적으로 기타수익/기타비용에 연결되며 상세에서 계정을 바꿀 수 있습니다.

수동 분개는 기초잔액·미지급·차입·이체 등 복수 행을 지원합니다. 각 행은 한쪽에 양의 정수만 입력하며 차변 합계=대변 합계를 저장 전에 검증합니다. 사용하지 않는 계정과 마감 연도에 새 분개를 만들 수 없습니다.

정정은 이전 분개를 같은 원본 일자에 역분개하고 새 분개를 추가합니다. 취소는 원본·헌금자 연결을 보존하고 역분개로 상쇄합니다. 따라서 과거 조회도 현재 정정 결과를 반영하며, 변경 이력은 별도로 남습니다. 수동 분개 취소는 역분개를 추가하고, 자동 분개는 원본 거래에서 취소해야 합니다. 이미 역분개된 항목을 중복 취소하지 않습니다.

## 7. 헌금과 원본 거래

헌금은 새로운 수입을 별도로 더하지 않고 `ACCT_LINK`로 원본 수입 한 건에 연결합니다. 개인 배분 행이 여러 개여도 총헌금은 원본 거래를 한 번만 합산합니다. 한 명이면 해당 금액을 연결하며, 공동 헌금은 배분을 확인하기 전까지 미배분 그룹으로 표시합니다. 배분 합계 불일치·원본에 없는 사람은 거절합니다. 수정 후 기존 배분이 더 이상 맞지 않으면 임의 재배분하지 않습니다.

헌금자와 헌금 종류는 비활성화해도 과거 내역에 남습니다. 기존 비활성 헌금 종류는 과거 거래에서 정정할 수 있지만 새 거래에 선택할 수 없습니다.

## 8. 메뉴와 화면

기존 앱의 **회계·헌금·통계** 메뉴에서 대시보드, 거래·분개 원장, 헌금 관리, 헌금자, 계정과목, 재무상태표, 통계, 재무상태 보고서, 외부 조회를 엽니다. 기존 데스크톱 계정으로 다시 로그인합니다. 관리자만 새 화면에서 수정할 수 있습니다. 일반 사용자는 재무 요약을 읽을 수 있습니다.

공동 헌금 입력 시 PC에서는 여러 헌금자를 선택하고, 개인별 연간 표의 월 금액을 누르면 해당 사람·월 필터가 적용됩니다. 기존 데스크톱의 그룹 입력도 유지했습니다.

## 9. 그래프

외부 CDN·분석 서비스 없이 공통 SVG 컴포넌트로 막대·꺾은선·혼합·누적 막대·원형·도넛을 렌더링합니다. 각 그래프의 표는 같은 집계 배열을 사용합니다. 월·분기·연도, 누적 흐름, 계열 숨김, 값 표시, 표/그래프 전환, SVG 저장을 제공합니다. 자산·부채·순자산 같은 잔액은 누적으로 다시 더하지 않습니다.

원형·도넛은 선택한 첫 계열의 구성비입니다. 합계 0 또는 음수 구성비는 오해를 막기 위해 막대·꺾은선을 안내합니다. 숫자 표는 계속 표시됩니다. 막대/점·월/헌금자 셀·계정별 구성에서 상세를 열 수 있습니다. 공개 화면에서는 집계 상세만 제공하고 개인 거래로 이동하지 않습니다.

## 10. 재무상태표와 보고서

기준일까지 누적 자산·부채·순자산을 계산합니다. 순자산은 순자산 계정과 미처분 누적 운영결과를 합한 값이며 **자산-부채-순자산=0**을 확인합니다. 지출이 없다는 의미와 부채가 없다는 의미를 구분하고, 부채가 0이면 안내 문구를 표시합니다.

요약/상세 보고서는 핵심 카드, 월별 흐름, 자산·부채·순자산 추이, 구성, 객관적 금액 요약을 사용합니다. 상세에는 헌금 추이, 수입·지출 구성, 전년·이전 기간 비교와 재무상태표를 추가합니다. 완전한 달은 직전 달, 완전한 해는 직전 해와 비교하고 그 외에는 같은 길이의 직전 기간을 사용합니다. 전년 동일 기간도 함께 표시하며 비교 기준 0은 비율을 계산하지 않습니다.

A4 인쇄 스타일에 제목·기간·생성일·페이지 번호·표·SVG를 포함했습니다. 브라우저 인쇄의 PDF 저장을 사용합니다. 페이지 수와 줄바꿈은 데이터 양과 브라우저에 따라 달라집니다.

## 11. 공개 화면과 권한

기본 관리 서버는 `127.0.0.1:8765`에만 바인딩합니다. Argon2 해시를 확인하고 HttpOnly·SameSite 세션으로 로그인합니다. 변경 요청은 관리자 권한과 같은 출처를 검사하며 원본 서비스의 권한도 적용합니다. 비밀번호·권한 변경 후 기존 세션을 재검증합니다.

공개 ON을 직접 선택하면 별도 포트 **8766**을 열고 무작위 경로를 생성합니다. 서버는 공개 전용 허용 필드만 투영합니다. 이름·개인 ID·메모·개인별 배분·원본 거래·원본 계정 목록을 보내지 않습니다. 사용자 계정명이나 헌금 종류에 사람 이름이 들어 있어도 공개 라벨은 고정 분류로 바꿉니다. 공개 포트에는 변경 API가 없고, OFF하면 이미 발급된 주소도 404로 차단됩니다. 브라우저 캐시는 저장하지 않습니다.

같은 네트워크에서 실제 PC 주소가 표시됩니다. 여러 네트워크 어댑터/VPN이 있으면 올바른 LAN 주소인지 확인하세요. 인터넷 공개에는 별도 라우팅과 HTTPS가 필요합니다. 공개 HTTPS 프록시를 준비했다면 `-Dsai.public.origin=https://공개호스트`로 표시할 원점을 지정합니다. 이 속성 자체가 프록시나 인증서를 설치하지는 않습니다.

모바일 관리자 편집은 HTTPS를 준비한 경우에만 별도로 활성화합니다. `-Dsai.admin.origin=https://관리호스트:8765`와 선택적인 `-Dsai.admin.bind=바인딩주소`, 로컬 PKCS12 파일 경로 환경변수 `SAI_TLS_KEYSTORE`, 암호 환경변수 `SAI_TLS_PASSWORD`가 필요합니다. 비밀값을 저장소에 쓰지 마세요. 관리 포트 기본값은 로컬이며 외부 공개용 포트와 다릅니다.

## 12. 검증 결과

자동 테스트 **1,213개: 1,212 통과, 0 실패, 1 건너뜀**입니다. 건너뛴 항목은 기존 H2 fixture 생성용 테스트입니다. `test bootJar spotlessCheck`가 통과했습니다. 실제 Swing 데스크톱에서 숫자 네 자리로 관리자 생성·로그인·메인 화면 진입을 확인했습니다. 실제 Chromium에서 4자리 로그인, 헌금자 등록·수정·비활성화, 헌금 입력·취소, 그래프 6종, PC·태블릿·모바일 터치, A4 PDF 생성과 공개 ON/OFF를 검증했습니다. 합성 V3→V4 데이터의 원본 건수·수입·지출 보존과 개인정보 제외도 통과했습니다. 마지막 비고·공동 배분 보존 보완 후 통합 테스트 15개와 브라우저 검증을 다시 실행해 모두 통과했습니다. 자동 테스트는 운영 자료를 사용하지 않습니다.

개발 환경의 기본 검증:

```sh
JAVA_HOME=/workspace/.toolchains/jdk-25.0.5+8 \
GRADLE_USER_HOME=/workspace/.gradle-steward \
./gradlew --offline --no-daemon --max-workers=2 test bootJar spotlessCheck
```

실제 브라우저 검증은 Playwright Core와 Chromium이 있는 개발 환경에서 선택적으로 실행합니다. 앱 사용자는 Node.js가 필요 없습니다.

```sh
SAI_BROWSER_SMOKE="$PWD/tools/browser-smoke.cjs" \
SAI_PLAYWRIGHT_PATH=/개발용/playwright-core \
SAI_CHROMIUM=/usr/bin/chromium \
./gradlew test --tests '*FinanceIntegrationTest.httpBoundary'
```

이 테스트는 테스트 전용 사용자와 임시 H2에만 접근하며 실제 8765/8766 포트를 잠시 사용합니다. 테스트 실행 전 같은 포트의 운영 앱을 종료하세요.

## 13. 발견한 문제와 수정

- 원본 비밀번호 패턴 제한이 숫자 네 자리를 거부하던 문제 → 공통 길이 정책으로 변경
- H2의 상수 IN 제약식이 migration 이후 닫힌 세션을 참조하던 문제 → 동등한 정규식 유형 제약으로 해결
- 원본 삭제가 거래·헌금자 이력을 없애던 문제 → 소프트 취소·역분개와 사용된 헌금자 비활성화
- 공동 헌금을 한 사람으로 덮어쓸 가능성 → 복수 선택과 배분 검증
- 비활성 계정 때문에 취소 역분개가 막히던 문제 → 역분개에서 기존 계정 허용
- 윤년·달 길이에 따른 전월 비교 경계 → 달/연도 비교 경계 별도 계산
- HTML hidden 속성이 레이아웃 CSS에 가려지던 문제 → 숨김 스타일 우선 적용
- Windows 도우미가 수정 전 원본을 실행하던 문제 → 수정본 빌드·패키지로 전환

## 14. 제한사항

- Windows 전용 exe의 직접 실행은 Linux 작업환경에서 검증할 수 없습니다. 여기서 제공하는 ZIP은 체크섬 검증된 원본 Windows 런처, 수정 JAR, 공식 Windows 전체 Java 런타임을 조립한 것입니다. Windows의 GitHub Actions 빌드는 런처까지 새로 만듭니다.
- 실제 운영 DB의 전후 검증은 아직 수행하지 않았습니다. 합성 V3 DB → V4 migration에서는 원본 건수·총수입·총지출 보존을 검증합니다.
- 이전 SQLite·엑셀 자동 변환, 외부 인터넷 호스팅·인증서·라우터 설정은 이 배포본이 자동 수행하지 않습니다.
- 비교율·반올림은 표시용이며 회계 금액 합계는 정수입니다. 그래프는 막대한 항목 수에서 표보다 읽기 어려울 수 있습니다.
- 미확정 과거 거래와 기초잔액을 검토하기 전의 복식부기 보고서는 전체 교회 재정을 완성한 장부가 아닙니다.

## 15. 사용 전 확인

1. 기존 앱에서 백업하고 새 버전을 별도 폴더에 압축 해제합니다.
2. Windows에서 실행·4자리 비밀번호·기존 백업 복원을 확인합니다.
3. 회계 연도·예산·운영 통장과 REVIEW 거래를 확인합니다. 기초잔액은 근거를 확인해 수동 분개합니다.
4. 원본 수입/지출 합계와 회계 연결 완료분의 합계를 대조합니다. 마감 전에 자산=부채+순자산을 확인합니다.
5. 소액 테스트 헌금·수정·취소·연간 표·PDF의 실제 프린터 출력을 확인합니다.
6. 공유가 필요하면 같은 네트워크 스마트폰에서 확인하고 OFF 후 접속 차단을 확인합니다.
7. 업데이트 후에도 `data/`와 `application.yml`, 별도 백업 파일을 함께 보관합니다.
