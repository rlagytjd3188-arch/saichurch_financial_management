# 검증 기록

2026-11-02, Node.js 24.19.0 / Chromium / Linux 환경에서 확인했습니다.

- npm ci: 잠금 파일 기준 재설치 성공
- npm test: 회계·무결성·CSV/XLSX 21개 테스트 통과
- npm run typecheck: 통과
- npm run build: 프로덕션 빌드 통과
- npm run test:e2e: 새 임시 DB에서 브라우저 통합 검증 통과
  - 계정과목 등록, 수입·지출 입력, 분개 상세
  - 은행 CSV 업로드 → 열 매핑 → 원본 저장 → 분류 → 장부 반영
  - CSV/XLSX 8개 다운로드와 JSON 백업
  - 교차 출처 변경 요청 차단
  - 1440px 데스크톱·390px 모바일, 가로 넘침 없음, JS 오류 없음
- 외부 viewer 모드 별도 실행: 인증 없는 조회 거절, data/import/publish 쓰기 거절

실제 Supabase 프로젝트·Auth 허용 사용자·RLS와 실제 HTTPS 호스팅은 연결하지 않았습니다. 외부 게시 및 로그인 성공 흐름은 배포 후 추가 검증이 필요합니다. 사용자 실제 은행 샘플과 기존 장부도 아직 제공되지 않아 실제 자료의 호환성과 잔액 대사는 검증하지 않았습니다.

모든 테스트 거래는 임시 DB에서 생성했습니다. 기본 운영 data 폴더에는 샘플 데이터를 넣지 않았습니다.

## 기존 교회 장부 가져오기 추가 검증

- 회계/HTTP/다중 시트 가져오기 테스트 총 34개 통과
- 프로덕션 빌드 및 TypeScript 검사 통과, /api/workbook 경로 포함 확인
- 브라우저에서 합성 XLSX 선택 → 연도/계좌/계정 확인 → 원본 저장까지 통과
- 실제 제공 XLSX는 별도 임시 DB에서 분석·2026년 가져오기·재가져오기 검증. 분개 자동 확정 없음, 동일 원본 중복 없음
- 원본 수식·잔액 불일치를 수정하지 않고 표시하는 동작 확인
- 실제 파일·개인 식별정보·생성된 DB는 Git에 포함하지 않음

## 빈 병합 셀 업로드 오류 수정

- 실제 제공 파일을 일반 은행파일 경로에 넣으면 ExcelJS MergeValue.toString에서 null 예외가 발생하는 문제 재현
- 빈 병합 셀·수식 결과 없음·수식 결과 0을 안전하게 읽는 공통 처리 추가
- 어느 업로드 버튼을 사용해도 교회 통장 형식은 기존 장부 검토 화면으로 자동 연결
- 테스트 총 37개와 프로덕션 빌드 통과
- 실제 원본 파일 분석 성공, 일반 업로드 버튼을 사용하는 브라우저 회귀 테스트 추가

- 실제 새 파일을 별도 임시 DB에서 분석: 기본 기간 8월 이후 정리 거래 207건, 일반 수입·비용 205건과 대납 검토 대상 2건

- 정리장부 보류 내역을 대시보드·보고서에 경고하고 원본 보고/계획 자료 별도 보존
