# 사이교회 사용자 정리장부 가져오기

## 확정된 자료의 역할

사용자 확인: 인수인계 시점은 **2026년 8월**, 이후 **통장 1개**로 운영합니다.

| 시트 | 앱에서의 역할 |
| --- | --- |
| 내역 | 사용자가 정리한 거래 원장. 8월 이후 선택 거래의 날짜·코드·내역·입금·출금·비고를 반영 |
| 계정 가이드 | 계정 코드·명칭·수익/비용 유형. 100 이월과 221 이체는 수익·비용 계정으로 만들지 않음 |
| 예산집행 | 연간 지출예산과 수입 목표를 연결. 집행 합계와 월별 보고 수치는 대조용으로 보존 |
| 정리한 것 | 종합 보고·정기 지출·약정 계획 원본 참고자료로 보존. 실제 거래로 재반영하지 않음 |
| 시트19 | 월간보고 초안 참고자료로 보존. 내역과 겹치는 합계를 분개에 더하지 않음 |
| 약정헌금 내역 / 입출금통장 내역 / 저금통장 내역 / 선교헌금 내역 | 인수인계 전 참고자료. 거래·분류 추천·기초잔액·보고서 계산에서 제외 |

이전 버전에서 네 통장 시트를 거래 원본으로 해석했던 방식은 이 파일에 적용하지 않습니다. 새 버전은 해당 시트만 있는 파일도 거래로 가져오지 않습니다. 다른 일반 은행 파일 가져오기 기능은 별도로 유지합니다.

## 사용 순서

1. 앱 종료 → GitHub Desktop에서 Fetch origin → Pull origin → Start-Windows.cmd 실행.
2. 은행내역 가져오기 → 기존 교회 장부 XLSX 선택. 일반 파일 선택/드래그를 사용해도 자동 인식합니다.
3. ‘사용자 정리장부 기준’ 표시와 **2026-08-01 이후 기간**을 확인합니다. 월만 확인된 상태이므로 기본 시작일은 8월 1일이며 정확한 관리 시작일에 맞게 조정할 수 있습니다.
4. 기존 운영통장을 선택하거나 ‘사이교회 운영계좌 만들기’를 선택합니다. 실제 금융기관·계좌번호는 추정하지 않습니다.
5. 실제 인수인계 당시의 **첫 거래 전 운영통장 잔액**을 알면 기초잔액 옵션에 직접 입력합니다. 이전 월의 이월액·통장 참고자료·누적잔액 수식에서 자동 추정하지 않습니다. 잔액 미등록 시 자금 화면에는 가져온 기간의 증감만 표시하고 경고합니다.
6. 계정 가이드 등록을 확인합니다. 기존 코드와 이름·유형이 충돌하면 중단합니다.
7. 일반 수입·지출 모두 선택 또는 개별 선택 후 원본 코드·메모·계좌를 검토합니다. 필요하면 거래별 계정·계좌를 지정합니다.
8. 대납은 자동 선택하지 않습니다. 실제 교회 통장에서 지급한 비용인지, 비용 발생·미지급 부채인지 확인하고 사유를 입력해야 합니다. 확인하지 못한 거래는 보류하세요.
9. 221 이체는 비용으로 바꿀 수 없고 보내는·받는 실제 계좌를 모두 지정해야 합니다. 인수인계 이전 이체는 범위 밖이므로 반영하지 않습니다.
10. 예산집행의 지출예산 및 수입 목표를 계정에 직접 연결합니다. 미연결 항목은 제외합니다. 여러 계획 항목을 같은 계정에 연결하면 합산합니다.
11. 확인 체크 → 선택한 정리 거래 반영. 기존 분류가 있는 선택 거래는 자동 분개하여 즉시 원장과 보고서에 반영합니다.
12. 대시보드/미분류 거래의 정리장부 보류 내역을 확인합니다. 같은 파일을 다시 열어 보류 거래만 선택·확인해 추가 반영할 수 있습니다.

보고서는 관리 시작 이후 자료이며 2026년 전체 교회 실적이라고 볼 수 없습니다. 연간 계획 대비 실적에도 이 기간 제한이 적용됩니다. 기존 엑셀의 계산 오류를 숫자에 맞추려고 조정분개하지 않습니다.

## 보존과 추적

- 거래 상세에서 원본 ‘내역 몇 행’과 코드·메모·원본 셀 값을 확인할 수 있습니다.
- 기존 장부 참고자료 메뉴에서 정리한 것·예산집행·시트19·계정 가이드와 인수인계 전 정리 내역을 조회합니다. 셀의 수식은 실행하지 않고 저장된 값만 표시합니다. 긴 계좌번호 형태는 마스킹합니다.
- 업로드 XLSX는 PC의 data/workbook-previews에 보존합니다. 원본 파일 자체는 외부 조회 사본에 게시하지 않습니다.
- 사용자 정리자료·이력·수입 목표는 JSON 백업과 외부 조회 사본에 포함됩니다. 금융 DB와 파일을 완전히 보관하려면 앱 종료 후 data 폴더 전체를 복사하세요.

## 중복과 기존 데이터

선택 거래의 원본 값과 같은 값의 반복 순번으로 식별키를 계산합니다. 같은 파일을 다시 가져와도 분개·기초잔액·동일 계획을 중복 생성하지 않습니다. 날짜·금액·내역이 같은 정상 반복 거래는 각각 보존합니다. 이미 가져온 원본 행이 변경되면 자동 덮어쓰기 대신 정정 안내를 표시합니다.

같은 기간에 이전 은행 원본 또는 별도 수동 거래가 있으면 중복을 막기 위해 중단합니다. 이전 버전에서 잘못 가져온 참고자료는 자동 삭제하거나 역분개하지 않습니다. 기존 자료를 보존·대조한 뒤 별도 빈 원장을 사용하거나 가져올 기간을 나누세요. 초기화가 필요하면 앱을 종료하고 data 폴더를 백업 이름으로 바꿔 보관하세요. 기존 백업을 덮어쓰지 마세요.

계정·계좌·기초잔액·선택 거래·원본 연결·예산·목표·감사 기록은 하나의 DB 트랜잭션으로 처리합니다. 어느 단계에서든 실패하면 전체가 롤백됩니다. 자동 연말 마감·이월 기능은 이번 수정에 포함하지 않습니다.

## 검증

실제 제공 파일은 별도 임시 DB에서 8월 이후 가져오기와 재가져오기를 검증했습니다. 실제 파일·개인 이름·재정 금액·생성 DB는 Git에 포함하지 않습니다. 자동 테스트는 합성 데이터만 사용합니다. Windows 자체 실행은 사용자 PC에서 추가 확인해야 합니다.
