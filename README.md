# 새이음 재정

PC에 원본 SQLite 원장을 저장하고, 선택적으로 외부 조회용 사본을 게시하는 교회 재정관리 앱입니다. 실제 재정 데이터와 샘플 데이터를 섞지 않으며 처음에는 빈 장부로 시작합니다.

## PC에서 실행

Node.js **24 LTS**가 필요합니다. 최초 설치·업데이트에는 인터넷이 필요하고 설치 후 PC 회계 업무에는 인터넷이 필요하지 않습니다.

```bash
npm ci
npm run build
npm start
```

같은 PC의 브라우저에서 `http://127.0.0.1:3000`을 엽니다. 서버를 종료하면 앱도 종료됩니다. PC 원본 서버는 외부에 공개하지 마세요. `npm run dev`는 개발용입니다.

1. 계정과목에서 기존 교회 장부의 계정을 등록합니다. 상위 계정과 하위 계정의 유형은 같아야 하며 분개는 최하위 계정에만 가능합니다.
2. 계좌 메뉴에서 실제 계좌마다 고유한 자산 계정을 연결합니다.
3. 거래 입력 → 기초잔액에서 자산·부채·순자산을 차변·대변으로 입력합니다.
4. 수입·지출·이체를 직접 입력하거나 은행 파일을 가져옵니다.
5. 미분류 거래의 추천을 확인하고 분류를 선택한 뒤 장부에 반영합니다.
6. 잔액 대사를 수행하고 보고서를 확인합니다.

은행 CSV/XLSX는 첫 번째 시트, 첫 번째 행이 헤더인 파일을 지원합니다. 은행 안내문·병합 제목이 앞에 있으면 이를 제거한 작업용 사본을 사용하세요. 날짜·입금·출금·거래 후 잔액 열이 필요합니다. 열 매핑을 제공하며 원본 행은 DB에 보존합니다. 원본 파일 자체는 별도 보관하세요. CSV는 UTF-8 및 EUC-KR을 지원합니다. XLSX 계산식은 계산하지 않으며 저장된 표시값을 읽습니다.

**이체:** 출금 원본에서 자금이체를 선택하고 받는 계좌 및 같은 날짜·금액의 입금 원본을 연결합니다. 입금 원본을 별도로 수익으로 반영하지 마세요. 다른 날짜에 걸친 이체는 고급 일반분개로 이체중 자산을 사용하는 등 별도 확인이 필요합니다.

## 저장 및 백업

기본 저장 경로는 `data/finance.sqlite`입니다. `.env.local`에서 `DATA_DIR`을 변경할 수 있습니다. SQLite WAL 모드와 트랜잭션을 사용합니다. 원 단위 금액은 정규화된 정수 문자열로 저장하고 `BigInt`로 계산합니다. SQLite NUMERIC/REAL의 자동 변환을 피하기 위한 선택입니다.

- 앱 내 JSON 백업: 모든 원장과 설정·은행 원본 행·이력을 내려받습니다. 자동 가져오기/복원 기능은 아직 없습니다.
- 완전한 복구용 백업: **앱을 종료한 상태에서 data 폴더 전체**를 외장 디스크 등에 복사합니다.
- 복구: 앱을 종료하고 현재 data 폴더를 보존한 뒤 백업 폴더를 원래 경로에 복사합니다. 동일한 앱 버전으로 실행하고 잔액과 분개 건수를 확인합니다. 운영 DB를 실행 중 덮어쓰지 마세요.

## 스마트폰 외부 조회 배포

PC가 꺼져 있어도 마지막 게시 자료를 볼 수 있습니다. 외부 서버에서 PC DB를 직접 열지 않습니다.

1. 전용 Supabase 프로젝트에서 `supabase/schema.sql`을 실행합니다.
2. Auth의 공개 회원가입을 끄고 조회 사용자 계정을 생성합니다.
3. SQL 편집기에서 조회 사용자의 UUID를 허용 목록에 추가합니다.
   ```sql
   insert into public.approved_viewers(user_id) values ('사용자의 실제 UUID');
   ```
4. PC의 `.env.local`에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 설정한 후 앱을 재시작합니다. 키를 Git에 올리지 마세요.
5. PC에서 백업 및 게시 → 조회 자료 게시를 누릅니다. 전체 거래처·은행 원본 행·수정 이력을 포함한 자료가 전송됩니다.
6. 별도의 Next.js 지원 HTTPS 호스팅에 같은 코드를 배포합니다. 외부 환경에는 `APP_MODE=viewer`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`만 설정합니다. **서비스 역할 키와 PC DB는 외부 배포에 넣지 않습니다.** 호스팅의 실행 명령은 `next start --hostname 0.0.0.0` 등 제공자 지침을 따릅니다. PC용 npm start는 의도적으로 루프백에만 바인딩합니다.
7. 스마트폰에서 배포 주소에 접속해 로그인합니다. API·RLS 모두 쓰기를 차단하며, 허용 목록에 없는 인증 사용자는 자료를 읽을 수 없습니다. 사용자 제거 시 다음 자료 요청부터 접근이 차단됩니다.

게시 함수는 단일 DB upsert로 스냅샷 전체를 교체합니다. 전송 실패 시 이전 게시 자료를 유지합니다. 외부 로그인 세션 만료 시 다시 로그인해야 합니다. 외부 사용자는 화면 복사뿐 아니라 보고서 CSV/XLSX도 내려받을 수 있습니다. 전체 복원용 JSON 백업은 PC 전용입니다.

외부 서버와 계정은 아직 연결/배포되지 않았습니다. 로컬 모드에서는 Supabase 설정 없이 사용할 수 있습니다.

## 검증

```bash
npm test
npm run typecheck
npm run build
```

브라우저 통합 테스트는 설치된 Chromium과 프로덕션 빌드가 필요합니다. 테스트 스크립트가 **매 실행마다 임시 DB**와 3105 포트의 서버를 만들고 종료합니다. 실제 원장에는 테스트 데이터를 넣지 않습니다.

```bash
# Linux 예시. Windows/macOS는 Chromium 실행 파일 경로 지정
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

`TEST_URL`을 지정하면 서버를 자동 생성하지 않고 해당 서버를 사용하므로 반드시 별도 테스트 원장을 지정하세요. 스크린샷은 `/tmp/church-artifacts`에 저장됩니다.

## 현재 범위와 제한

- 구현: 계정 추가/비활성화, 연도 추가, 계좌 등록, 기초잔액/일반분개, 자동 수입·지출·이체·미지급 발생/지급, 역분개 취소, 원장, 예산 개정 이력/경고, 은행 CSV/XLSX 검토·중복 방지·이체 연결, 추천 규칙, 잔액 대사, 대시보드, 월간/연간/재무상태표/계정별 원장, 내보내기, JSON 백업, 외부 조회 모드/게시.
- 정정은 취소 후 새 거래 입력의 두 단계입니다. 잘못된 은행 거래를 취소해도 은행 원본의 중복 방지 연결은 남습니다. 올바른 분류는 수동 거래로 다시 입력하고 이력에서 원거래를 추적하세요.
- 자동 이월/마감/재개방, JSON 자동 복원, 계정명·계좌명 편집, 첨부 증빙, 사용자 관리 UI, 기금별 목적 잔액은 미구현입니다. 기존 Sheets의 통장/계정/예산 가져오기는 아래 전용 기능을 사용하세요.
- 현재 회계연도는 1월~12월입니다. 지정 목적 헌금은 계정과목으로 분류할 수 있지만 기금별 잔액 장부는 아직 없습니다.
- 재무상태표는 선택 연도의 개시분개와 당기 분개로 계산합니다. 다음 연도에는 기초잔액을 직접 등록해야 합니다. 기초잔액이 없으면 실제 총자산을 나타내지 않습니다.
- 월간·연간보고는 자금 증감과 수익·비용 운영결과를 구분합니다. 예산 집행액은 비용 발생 기준이며 미지급 비용도 포함합니다.
- 실제 Sheets·예산안·은행 샘플 매핑과 운영 자료 대사를 마치기 전에는 기존 장부를 대체하지 말고 병행 확인하세요.

설계와 배포 전 점검은 `docs/architecture.md`를 참고하세요.

## 기존 Google Sheets 전체 장부

「은행내역 가져오기」 상단의 **기존 교회 장부 가져오기**에서 전체 XLSX를 선택하세요. 여러 통장 시트, 계정 가이드, 지출예산을 함께 검토하고 가져올 수 있습니다. [자세한 안내](docs/workbook-import.md)를 확인하세요. 이 기능은 은행 원본을 먼저 저장하고 사용자가 분류를 확인한 뒤 분개합니다. 원본의 잔액 불일치는 그대로 표시하며 자동 보정하지 않습니다.
