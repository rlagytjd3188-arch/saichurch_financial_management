# 사이교회 재무관리 1.5.2

[1.5.2 변경 안내](docs/updates-1.5.2.md): 주간·월간·연도 보고서 막대그래프의 맨 오른쪽에 해당 기간의 수입·지출·헌금 합계를 추가했습니다.

교회 수입·지출·예산을 관리하는 Windows 데스크톱 프로그램입니다. 기존 청지기 프로그램을 기반으로 **복식부기, 개인별 헌금, 재무상태표, 그래프 보고서와 읽기 전용 공유 화면**을 추가했습니다.

## Windows에서 바로 실행

1. 이 대화에서 제공한 **사이교회 수정본 Windows ZIP**을 내려받고 압축을 전부 풉니다.
2. `ChurchSteward` 폴더 안의 **ChurchSteward.exe** 또는 **Start-Windows.cmd**를 실행합니다.
3. 처음 실행할 때 관리자 비밀번호를 설정합니다. **4~64자**이며 숫자 네 자리도 가능합니다.
4. 기존 메뉴에서 회계 연도·예산을 먼저 등록합니다. **회계·헌금·통계** 메뉴를 누르면 새 관리 화면이 브라우저에서 열립니다. 같은 데스크톱 계정으로 로그인합니다.

Java가 포함된 ZIP은 Node.js나 별도 Java 설치가 필요 없습니다. 실행 중에는 프로그램을 켜 두세요. 데이터를 저장하는 `data/`와 암호화 설정 `application.yml`은 프로그램 폴더에 생깁니다. 이 파일들은 GitHub에 올리지 않습니다.

GitHub에서도 수정본을 만들 수 있습니다: [Actions → Windows app](https://github.com/rlagytjd3188-arch/saichurch_financial_management/actions/workflows/windows.yml) → 성공한 실행 → Artifacts → `SaiChurch-Windows`. GitHub 로그인 후 아티팩트를 받고, 안의 프로그램 ZIP도 풀어 주세요. 이전 원본 공식 1.2.0 ZIP에는 이번 기능이 없습니다.

## 주요 기능

- 기존 데스크톱 수입·지출, 예산, 회계 연도, 가져오기·내보내기, 인쇄·PDF와 백업 기능 유지
- 수입·지출 자동 분개, 수동 분개·기초잔액, 차변=대변 검증, 취소·정정 역분개
- 계정과목·헌금 종류·헌금자 등록·수정·비활성화
- 원본 수입에 헌금 연결, 공동 헌금의 확인된 개인 배분, 월·연·헌금자·종류별 합계
- 개인별 연간 12개월 헌금표와 월별 상세 조회
- 헌금자별 월 약정액·시작/종료월 이력, 개인별·전체 약정헌금 달성률과 목표선 그래프
- 월별 ‘약정헌금 미납’ 표시, 외부 교회 명부·입금자명 연결과 별도 그래프 색상
- 약정(빨강)·주정(초록)·선교(보라)·감사(노랑)·외부 교회(주황) 구분, 나머지는 기타수입(회색)·지출(파랑)으로 합친 그래프
- 주간·월간 보고서 수입·지출 별지와 출력 범위 선택
- 기준일 재무상태표, 자산=부채+순자산 검증, 전월·전년 비교
- 막대·꺾은선·혼합·누적 막대·원형·도넛 그래프, 동일 집계 표, SVG 저장
- 요약·상세 재무보고서, A4 인쇄·브라우저 PDF 저장
- PC·태블릿·스마트폰 화면과 개인정보를 제외한 별도 읽기 전용 공유 서버

기존 거래는 자동으로 임의의 계정·헌금 종류에 배정하지 않습니다. **검토 필요(REVIEW)** 상태에서 원본을 확인해 회계 연결을 확정해야 복식부기 보고서에 포함됩니다.

## 다른 PC·스마트폰에서 보기

새 관리 화면의 **외부 조회 → 공개 ON**에서 공유 주소를 확인합니다. 같은 Wi-Fi/내부 네트워크에서 열 수 있고, PC 프로그램이 켜져 있어야 합니다. Windows 방화벽에서 필요한 경우 공유 포트 **8766**의 내부 네트워크 접근을 허용합니다. **공개 OFF**하면 기존 공유 주소도 차단됩니다.

공개 화면은 이름·개인 ID·개인별 배분·메모를 서버 응답에서 제외한 집계만 제공합니다. 기본 관리 화면은 해당 PC에서만 열립니다. 외부 인터넷 접속과 모바일 관리자 편집에 필요한 HTTPS 설정은 [상세 안내](docs/saichurch-1.3.md)를 참고하세요.

## 업데이트와 기존 자료

업데이트 전 기존 앱에서 백업 파일을 만드세요. 새 버전은 **별도 폴더**에 풀고 백업을 복원하는 방법을 권장합니다. `data/`와 `application.yml`을 따로 덮어쓰거나 초기화하지 마세요. V4 migration은 기존 H2 거래와 금액을 보존하면서 회계 테이블을 추가합니다.

예전 Next.js 웹앱의 SQLite 파일과 엑셀 파일은 그대로 보존되어 있지만 이 Java 앱의 H2로 자동 변환하지 않습니다. [코드 교체 이력과 자료 위치](docs/source-replacement.md)를 확인하세요.

## 소스 빌드

JDK **25**가 필요합니다. GitHub Desktop에서 Pull 후 **Build-Windows.cmd**를 실행하면 테스트·빌드 후 수정본을 실행합니다. 소스 폴더에서 Start-Windows.cmd를 실행해도 같은 빌드 절차를 사용합니다.

```sh
./gradlew --no-daemon --max-workers=2 test bootJar spotlessCheck
```

Linux/macOS 실행에는 GUI 환경이 필요합니다. 완성된 JAR를 `build/` 밖의 별도 폴더로 복사한 후 `java -jar church-steward-1.5.2.jar`를 실행합니다. `build/libs`에서 실제 장부를 운영하지 마세요.

Windows 배포본 전체 빌드: `gradlew.bat packageWindows`. 개발용 브라우저 검증 방법과 구현·DB·테스트 보고서는 [구현 상세 보고서](docs/saichurch-1.3.md)에 있습니다.
